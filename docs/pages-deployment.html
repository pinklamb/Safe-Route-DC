SAFEROUTE DC / PROJECT GUIDE

GitHub Pages publishing

The documentation site is deployed by GitHub Actions from the contents of the docs/ folder.

How publishing works

The workflow is .github/workflows/static.yml. It runs automatically when changes are pushed to main; it can also be started manually from the repository's Actions tab.

  1. 1
    Check out the repository

    GitHub Actions checks out the commit being deployed.

  2. 2
    Prepare GitHub Pages

    The workflow configures the Pages deployment environment and permissions.

  3. 3
    Upload the documentation

    The workflow uploads ./docs as the Pages artifact. docs/index.html becomes the site home page.

  4. 4
    Deploy the artifact

    The Pages deployment action publishes the uploaded static site.

Publish a documentation change

  1. Commit and push the documentation branch.
  2. Open a pull request into main and merge it.
  3. The push to main starts the Pages workflow.
  4. In the repository, open Actions and confirm Deploy static content to Pages completes successfully.
  5. Open Settings → Pages to find the live site address.

The workflow only runs automatically for pushes to main. A feature branch or an open pull request does not update the live site. Merge the changes to main to publish them.

Pages settings

In Settings → Pages, the publishing source should be set to GitHub Actions. The workflow grants the deployment permissions it needs and serializes deployments so two site releases do not run at once.

GitHub Pages hosts the documentation only. The route-planning app still runs as a Railway Docker service; Pages does not run Node.js, Express, or the MySQL-backed API.

Workflow source

The workflow source is maintained with the repository at .github/workflows/static.yml. It uses GitHub's Pages configure, artifact upload, and deploy actions. The artifact path is ./docs so the project source, local config, and non-doc assets are not published as part of this site.

SAFEROUTE DC / PROJECT GUIDE

Railway deployment

Deployment notes for the Railway-hosted, Docker-based Node.js service, including process startup, port handling, database variables, and source-repository gaps.

Deployment target

SafeRoute DC is deployed as a Docker-based service on Railway. The container runs the Node.js application; Railway supplies the runtime port and service environment.

Repository note: this checkout has no committed Dockerfile, railway.toml, or railway.json. The Docker build configuration is therefore controlled in Railway or maintained outside this repository. The exact image build settings cannot be reproduced from this checkout alone.

Runtime contract

  • Runtime: Node.js 22.12, as declared in package.json.
  • Process: node server.js.
  • Port: reads PORT; defaults to 4000 for local development.
  • Health behavior: the HTTP app starts while the background process connects to MySQL and syncs crime data.

The current package.json has no start script. If a Railway service is configured to run npm start, add that script or change the Docker command to node server.js.

Railway variables

Set the database connection values in the Railway service's Variables panel:

VariablePurpose
DB_USERMySQL user
DB_PASSWORDMySQL password
DB_SERVERMySQL host
DB_NAMEDatabase/schema name
DB_PORTMySQL port

Railway provides the app's PORT value. Keep secrets in Railway's variable store or an ignored local .env file; never add real credentials to the repository or documentation.

Database and background sync

The app expects a reachable MySQL database with a crimes table. At startup, a background task connects and syncs DC GIS data. It schedules another attempt about once an hour, including after a failed attempt. The deployment therefore needs outbound access to both the database and the DC GIS Feature Service.

Deploy checklist

  1. Confirm Railway's Docker build context and Dockerfile path.
  2. Set the database variables in the Railway service.
  3. Ensure the container launches node server.js and binds through Railway's PORT.
  4. Confirm the MySQL database and crimes table are reachable.
  5. Review startup logs for the database connection and data refresh outcome.

SAFEROUTE DC / PROJECT GUIDE

How it works

A route request passes from the browser through the Express API, which looks up nearby records and returns a score for each option.

From locations to route options

  1. 1
    Choose a start and destination

    The browser page accepts locations and uses Google Maps services to resolve places and request walking directions.

  2. 2
    Draw the route alternatives

    The app receives route alternatives, decodes each route polyline into latitude/longitude points, and draws them on the map.

  3. 3
    Ask the API for a score

    For each alternative, the browser posts its route points to /api/safetyScore.

    { "route": [{ "lat": 38.90, "lng": -77.03 }, ...] }
  4. 4
    Score nearby crime data

    Express queries the MySQL crime table around the route, applies the scoring rules, and returns the score and route distance.

  5. 5
    Compare the results

    The browser colors the alternatives and displays a score label with route distance and estimated travel time.

Score response

FieldMeaning
safetyScoreRounded route score from 0 to 100; higher values mean less weighted incident density under this heuristic.
weightedPerKmWeighted nearby incident total divided by the route distance baseline.
routeDistanceKmRoute distance measured between the supplied route points, in kilometers.

For formulas and the complete parameter list, see the safety scoring model. For system boundaries, see Architecture.

Architecture

How the browser, Railway Docker service, Express API, MySQL database, and DC GIS crime feed fit together.

System overview

The browser owns the map interaction. The Railway service hosts the Node.js/Express application. Express uses MySQL for crime records, while a scheduled task refreshes those records from the DC GIS service.

Crime data flow

  1. At process startup, the scheduled updater connects to the MySQL pool and begins a data refresh.
  2. The updater checks DC GIS crime layers for years 2018 through 2025 and requests records in batches of up to 1,000.
  3. Each batch is loaded through a temporary staging table, then inserted or updated in crimes.
  4. The updater waits three seconds between batch requests and schedules another run after approximately one hour.
  5. Score requests query MySQL using a route bounding box, then perform a distance check against route points.
Data and app are separate services. The map/directions service, Railway container, MySQL host, and DC GIS endpoint are connected over network APIs. This repository does not contain the crime data itself.
